# 二次发放需求（定稿）

> **状态**：现行有效定稿（2026-08-27）  
> **说明**：本文取代此前各文档中关于「二次/三次发放、失败处理发起重发」的旧口径。  
> 旧描述已在相关文档中标注**废弃**，实现与验收以本文为准。

---

## 1. 目标

在支付计划生成页选择「二次发放」，将**更早业务期、正常发放计划中银行失败、且尚未重发成功**的明细，汇总为**当前业务期**的一条二次发放计划，再走与正常计划相同的复核 → 审批 → 财务 → 银行链路。

「二次发放」为功能名称，实际含义为**失败补贴重发**，轮次无上限。

---

## 2. 入口与范围

| 项 | 定稿 |
|----|------|
| 入口 | **仅**支付计划生成页（核定方式 = 二次发放） |
| 失败处理页 | 仍只读列表，**不**提供发起重发 |
| 同月唯一 | 同一业务期 + 同一补贴类型，仅允许一条未删除的二次计划 |
| 与正常计划 | 同月可同时存在一条正常计划 + 一条二次计划 |

---

## 3. 候选明细规则

纳入二次计划预览/保存的源明细须同时满足：

1. 所属计划 `determination_type = normal`（**排除**二次计划自身的失败行，防止金额翻倍）
2. 明细 `distribution_result = failed`
3. 源明细未标记「重发成功」（见第 5 节 `retry_status`）
4. 源明细业务期 **严格早于** 当前二次计划业务期（`<`）
5. 补贴类型与当前计划一致
6. 人员主数据存在；对应补贴类型存在 **approved** 且**在发**的核定；开户名/账号/发放机构齐全  
   - 不满足则**静默不纳入**，不做跳过提示
7. 同一人在不同历史业务期各有一笔失败 → **多笔都进**（各带原失败金额）

金额：取源失败行 `distribution_amount`；**不带**月标准、**不挂**新补发。

账号：生成时重取核定主数据的发放机构/开户名/银行账号。  
姓名、身份证、街道、村委会：取人员主数据。

预览/保存为全量合格名单，**不支持**勾选剔除（与现行正常计划一致）。

---

## 4. 数据字段（明细表）

在 `shebao_payment_plan_detail` 上：

| 字段 | 用途 |
|------|------|
| `source_detail_id` | 二次计划新明细指向源失败明细；正常计划为 null |
| `retry_count` | **源行**被纳入二次计划的次数；保存 +1，撤销 −1 |
| `retry_status` | **源行**独立状态；重发成功后为 `retry_success` |

不落「原始业务期」列；前端展示原始业务期时通过 `source_detail_id` 关联源明细的 `business_period`。

计划主表继续使用 `determination_type = second`，批次号规则继续使用类型码 `02`。

---

## 5. 状态与展示

| 场景 | 行为 |
|------|------|
| 纳入二次计划保存 | 源行 `retry_count + 1` |
| 撤销二次计划 | 源行 `retry_count - 1`（≥0）；可再次纳入 |
| 二次计划明细银行成功（批次完成） | 源行 `retry_status = retry_success`，不再进入候选 |
| 二次计划明细银行失败 | 源行不标重发成功，可再次纳入 |
| 源失败行展示 | `failed` + `retry_success` → UI 文案「重发成功」 |
| 二次计划成功行展示 | 照常「已发放」 |

---

## 6. 财务

二次计划财务审核通过后再次扣款；银行完成时失败金额退回账户（与现有支付计划结算一致）。原因：原始发放失败金额已在首次结算中退回。

---

## 7. 明确不做 / 已废弃的旧口径

以下旧说法**不再作为需求**：

- 从「失败处理」页发起二次/三次发放
- 严格二次 → 三次 → 人工封顶
- 支付计划页二次发放与失败重发是两套无关能力
- 二次发放再挂当月标准或新补发
- 预览勾选剔除部分人员
- 无核定/无账号时整单报错或提示跳过人数

权威以本文为准；实现见后续代码与 `sql/payment_plan_second_retry_*.sql`。

---

## 8. 验收要点

1. 仅 normal 历史失败进入当前月二次计划；二次失败行不进入下一次候选  
2. 多月同人失败 → 多笔都进  
3. 不在发 / 无账号 → 不在预览名单且无提示  
4. 同月同类型第二条二次计划 → 拦截  
5. 撤销后再生成，`retry_count` 正确加减  
6. 二次成功 → 源行「重发成功」且不再进候选；账户再扣
